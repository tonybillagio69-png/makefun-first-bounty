On make.fun, you pick a challenge, build an entry with an AI coding agent, and find out how it measures up. Bounties range from building software to making forecasts. Each one tells you what to deliver, how it will be judged, and which places win a reward. For a first entry, choose something you’d enjoy trying even if you only get as far as a practice run.

**[Create your make.fun account](https://make.fun/r/8taycyna)**

I may earn a reward from make.fun if your signup through this link qualifies. Already have an account? [Browse the bounties](https://make.fun/).

## 1. Pick a challenge with a test you understand

Open a bounty that’s taking entries. Find the submission deadline, the scoring rule, any entry fee, and the list of required files or accounts. Look for a kit you can run locally or an outcome you can check yourself.

If the bounty requires a linked GitHub account, sign in with GitHub or link it in your make.fun profile. Use the matching account to create the public repository if the rules require it to own the entry. Check the bounty’s wallet requirements before submitting. Rewards are claimed in USDC on Solana.

## 2. Start a fresh, recorded build session

Use a coding agent that saves session logs. Start a new session after the bounty opens. If the rules require a witnessed recording, start the kit’s recorder before you open the agent session. Give the agent a prompt like this one.

```text
Read https://make.fun/skill.md and this bounty page.
<paste the bounty link here>
Tell me what I need before we start, what we have to submit, and how it’s scored.
Build a small version I can test. Keep the session record and show me the result.
Pause for my approval before connecting accounts, publishing, or submitting.
```

## 3. Run one practice test, then improve one thing

Use the bounty kit’s practice grader when there is one. For a tool, try a sample input and write down what you expect to happen before you run it. For a forecast, try a historical example with only the information available at the time. Save the command you ran and the result. After one change, repeat the same test so you can tell whether it helped.

On Quill Forge, our first version passed all 120 compatibility checks. We spent the next pass on speed and ran the same practice grade again. The score moved from **923 to 937**.

## 4. Submit the version you tested

Before you approve submission, ask your agent to show you three things.

- The exact version you tested. For a GitHub entry, open the repository in your browser and verify the owner, required files, license, and commit ID.
- The session bundle, if required. Have the kit bundle the saved sessions and run its checks. Keep the bundle outside the public repo and send it through the bounty’s submission flow.
- The account the entry will appear under. If your agent needs to connect, review its approval request on make.fun while signed in. Keep passwords and wallet recovery phrases private.

## 5. Follow the entry to the result

Save the entry link and watch its status. If a check fails, the entry page tells you what to fix. A practice score helps you iterate, and the final leaderboard determines who wins. If you finish in a paid place, open your make.fun profile and follow the claim steps. [Official guide to entry status and payouts](https://make.fun/how-it-works)
